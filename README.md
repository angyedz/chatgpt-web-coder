## Как это работает

Ты отправляешь задачу в терминале. Harness управляет ChatGPT Web через браузер, а вызовы локальных инструментов проходят через MCP-коннектор и Secure MCP Tunnel. Результаты и ход работы отображаются в терминале.

```text
  твой проект      harness                 ChatGPT Web
  ───────────      ───────                 ───────────
  файлы        ◄── инструменты ◄── MCP ◄── запросы модели
  терминал         чат и план   ──────────► ответы и результаты
```

### Что умеет

| Работа с проектом | Работа с агентом |
| --- | --- |
| Файлы, патчи, команды и Git | Потоковый ответ, план и история действий |
| Фоновые процессы и таймеры | Сессии для каждого workspace |
| Веб-поиск через SearXNG | Контекст с настраиваемой компактацией |
| Внешние MCP-серверы | Skills и инструкции `AGENTS.md` |
| Подтверждение команд и записи файлов | Элементы ChatGPT Web: кнопки и поля в карточках |
| Обновление и откат из терминала Windows | Прокрутка истории и копирование текста мышью |
| Управление задачами из личного Telegram-чата | Один редактируемый статус, отмена и подтверждения |

## Быстрый старт

### 1. Установи на Windows

Скачай `chatgpt-coder-windows.zip` в разделе **Releases** репозитория, полностью распакуй архив и запусти `install.cmd` или выполни из его папки:

```powershell
.\install.cmd
```

Установщик загрузит собственные Node.js, Git, зависимости, Chromium и tunnel-client. Затем открой **новый** терминал, перейди в папку проекта и запусти:

```powershell
cd 'C:\путь\к\проекту'
chatgpt-coder
```

Для Windows-установщика нужны Windows 10/11, интернет и доступ к скачиванию зависимостей. Подробности и решение проблем — в [инструкции по установке](docs/INSTALL-WINDOWS.md).

### 2. Подключи инструменты

Для работы через MCP нужны аккаунт ChatGPT с доступом к custom MCP connectors, созданный Secure MCP Tunnel и runtime API key с правами **Tunnels Read + Use**. Войди в ChatGPT в открывшемся браузере, затем в harness введи:

```text
/connect tunnel tunnel_...
/connect key <runtime-ключ>
```

Создай в ChatGPT custom MCP connector с подключением через этот туннель. Пошаговая инструкция — [настройка Windows](docs/INSTALL-WINDOWS.md#3-подключить-chatgpt-и-инструменты) и [справочник](docs/REFERENCE.md#tunnel-и-коннектор-chatgpt).

### Запуск из исходников

Нужны Node.js 22+ и npm. Установи зависимости и браузер, затем запусти приложение:

```powershell
npm ci
npm run setup
npm run dev
```

Настроить соединение можно через `/connect`. Для локальной конфигурации доступны [.env.example](.env.example) и [harness.config.example.json](harness.config.example.json). При запуске из исходников рабочей папкой будет текущий каталог.

### Субагенты: только по команде

Субагенты **не запускаются по одной лишь инициативе модели**. Пользователь должен явно разрешить мультиагентную работу; после такого разрешения главный Orchestrator может делегировать задачи через MCP-инструменты `delegate_subagents`, `list_subagents`, `wait_subagents`, `message_subagent` и `stop_subagents`. Для ручного запуска в терминале используется команда:

```text
/swarm start 5 Проверь архитектуру, реализацию, тесты, надёжность и UX проекта
/swarm status
/swarm inspect 2
/swarm chat 2
/swarm open 2
/swarm message 2 Проверь ещё раз результаты
/swarm results
/swarm history
/swarm report <run-id>
/swarm stop 2
/swarm stop all
```

Допустимо от **1 до 5** субагентов. Их можно запускать, пока основная цель продолжает работать: каждый получает отдельную фоновую вкладку ChatGPT и **собственную локальную копию рабочей папки**. Незакоммиченные изменения копируются, но `.env`, приватные ключи, cloud credentials и другие файлы с секретами исключаются. Папка может не быть Git-репозиторием; субагенты не создают ветки, worktree, коммиты или PR. Нужен настроенный MCP-коннектор. Подтверждения опасных действий сохраняются.

При обычном видимом Chromium вкладки создаются через CDP с `background: true` и `focus: false`, без запроса переключения активного окна. Завершённые чаты остаются открытыми: `/swarm chat <id>` показывает их историю, `/swarm open <id>` выводит выбранную вкладку на передний план только по явной команде пользователя, а `/swarm message <id> <текст>` отправляет follow-up в тот же чат. В headless-режиме используются невидимые страницы. Если фоновое создание вкладки недоступно в видимом браузере, программа сообщает об ошибке вместо переключения фокуса. После завершения изменения автоматически переносятся в исходную рабочую папку **только если соответствующие файлы не менялись параллельно**. Если родительский агент или другой субагент изменил тот же файл иначе, он не перезаписывается: конфликт и путь к локальной копии показываются в отчёте. Копии сохраняются для проверки; остановка не удаляет написанный код. Статусы, списки интегрированных файлов и конфликты сохраняются в `~/.chatgpt-coder/swarm-reports/`; смотри `/swarm history` и `/swarm report <run-id>`.

Полный список с примерами — в [справочнике команд](docs/REFERENCE.md#команды-tui). Для веб-поиска нужен доступный SearXNG с JSON API; остальные инструменты могут работать без него.

В интерфейсе шкала контекста и прогресс плана показывают фактические оценки harness; индикатор ожидания не показывает выдуманный процент. Колесо мыши над историей и клавиши `PgUp`/`PgDn` прокручивают сообщения, стрелки `↑`/`↓` переключают предыдущие сообщения. Чтобы отключить анимацию, установи `CHATGPT_CODER_REDUCED_MOTION=1`.

В широком терминале цель, план, фоновые задачи и уведомления отображаются справа от истории чата. В узком окне они размещаются под историей.

Зажми левую кнопку и протяни по тексту сообщения: выделенный текст автоматически скопируется при отпускании. В буфер попадает только содержимое сообщений, без подписей и элементов интерфейса harness. Колесо мыши прокручивает историю. В терминалах вне Windows для копирования используется OSC 52, поэтому поддержка буфера обмена должна быть включена в настройках терминала.

Во время работы можно набрать `/btw <вопрос>`. Harness откроет отдельный временный чат, передаст ему ограниченный снимок текущей задачи, плана и последних сообщений и покажет ответ с пометкой `btw`. Основной агент продолжает работу и не получает этот вопрос или ответ. Снимок может быть неполным и устаревать. Одновременно выполняется один вопрос; `/btw cancel` останавливает его, не отменяя основную задачу.

### Управление из Telegram

Создай бота через [@BotFather](https://t.me/BotFather), затем в harness выполни `/telegram setup`. В появившемся замаскированном поле введи токен. Он проверяется через Telegram Bot API, но сохраняется локально только после привязки аккаунта. Открой личный чат с ботом, нажми **Start** и отправь три одноразовых слова, показанные в harness (можно просто текстом или как `/pair слово1 слово2 слово3`). Фраза действует 10 минут; разрешено до 5 попыток с одного аккаунта и 20 попыток всего. После привязки harness сохраняет Telegram user ID и chat ID: группы и остальные аккаунты игнорируются.

Токен не попадает в переписку, историю сессии или командную историю. На Windows он шифруется DPAPI для текущей учётной записи; на других системах файл учётных данных доступен только владельцу. Harness обращается к Telegram через HTTPS long polling, поэтому входящий порт открывать не нужно. Отозвать токен можно через BotFather; локально удалить его — `/telegram unlink`.

В личном чате отправляй обычный текст как задачу **или команды harness** (`/help`, `/status`, `/model`, `/effort`, `/goal`, `/swarm`, `/update settings`, `/update latest`, `/update apply`, `/mcp`, `/jobs` и другие). Команды вызывают реальный обработчик harness, а не отправляются как вопрос ИИ; результат или ошибка возвращается в Telegram. **После каждого сообщения бот создаёт отдельную карточку** и обновляет её по ходу работы. Длинные ответы команд приходят дополнительными сообщениями. Подтверждения опасных действий остаются в Telegram; действующий режим безопасности harness сохраняется. Пароли, токены и `/telegram setup` вводи только через локальные защищённые поля harness, а команды с локальным диалогом выбора файла используй с явным путём. Файлы, прикреплённые локально, автоматически к сообщениям Telegram не добавляются.

**Интерфейс Telegram с кнопками:** отправь /start — интерфейс бота на английском; доступны вкладки Tasks, Sessions, Model, Effort, Subagents, Tools, Updates и Settings. Для текстовых задач, путей, новых целей и сообщений агентам бот открывает поле ввода. Списки сессий и доступных моделей листаются кнопками, отдельным агентам можно отправлять follow-up или останавливать их. Опасные операции требуют подтверждения; все прежние slash-команды остаются доступными, а нестандартные операции — через Run a command.

**Полная доставка ответов:** карточка показывает предпросмотр, но законченные ответы ChatGPT и длинные результаты команд передаются полностью дополнительными сообщениями (до 3500 UTF-16 символов в одном). Локальная очередь сохраняет неотправленные части в ~/.chatgpt-coder/telegram/outbox-*.json, отправляет их по порядку и повторяет попытки при сбоях API, включая после перезапуска harness. Старые ограничения на 1600 символов карточки и 12 сообщений больше не обрезают полный ответ. Доставка — не менее одного раза: если процесс аварийно завершён между успешной отправкой и записью отметки, Telegram может получить повторную часть. Компьютер с harness должен быть запущен для доставки и повторных попыток; не удаляй файлы outbox, пока есть неотправленные сообщения.

**Сессии в разных папках:** `/sessions` показывает все сохранённые чаты, `/switch <id>`, `/session <id>` или `/session open <id>` выбирает один из них. `/session new` или `/new` создаёт новый чат в текущей выбранной папке. `/new <абсолютный путь>` открывает отдельную сессию в существующем каталоге, а `/new --create <абсолютный путь>` создаёт каталог и сессию; пути с пробелами можно взять в кавычки. `/session rename <название>` и `/session info` действуют на выбранный чат. `/folders` показывает сохранённые каталоги. Выбор сохраняется после перезапуска Telegram-бота. Удалённые сессии работают в собственных фоновых вкладках и папках, не заменяя локальный чат harness. `/goal`, `/status`, `/model`, `/effort`, `/swarm`, `/timer`, `/timers`, `/jobs`, `/job`, `/btw` относятся к выбранной Telegram-сессии. `/swarm` использует копии именно выбранного проекта, а изменения модели и thinking effort сохраняются отдельно для каждого чата. `/btw` отвечает в отдельной фоновой вкладке, не останавливая основной ход. Таймеры и процессы удалённой сессии остаются доступными между ходами, пока работает harness. Машинные команды вроде `/update`, `/mcp`, `/approval`, `/doctor` действуют глобально и явно помечаются как команды основного harness. В другой выбранной сессии `/attach <путь>`, `/attach folder <путь>`, `/attachments`, `/detach <id>`, `/compact`, `/agents`, `/skills` работают в её собственной папке и вкладке. Неподдерживаемая для удалённой сессии команда выдаёт ошибку вместо выполнения в локальном проекте. Для файлов из Telegram используй явные пути на компьютере с harness, а не локальный диалог выбора файла.

`/telegram stop` останавливает бота, сохраняя привязку и токен; `/telegram start` запускает его снова. `/telegram unlink` удаляет локальный токен и привязку.

История чата показывает сообщения и действия инструментов. Служебные ответы команд хранятся отдельно: `Ctrl+O` переключает чат и системный журнал. Результат команды открывается в журнале автоматически; полная история сохраняется в сессии.

Таблицы из ответов ChatGPT отображаются строками и выровненными колонками, включая таблицы без заголовка. Длинные ячейки переносятся; в очень узком окне таблица показывается вертикально. Старые сохранённые ответы с HTML-таблицами тоже преобразуются при отображении.

Если ChatGPT показывает интерактивную карточку, агент может перечислить её кнопки и поля через MCP, затем нажать кнопку или заполнить поле. В режиме `ask` harness запрашивает подтверждение перед действием; в режиме `never` агент действует по исходной задаче, не спрашивая в окне ChatGPT.

### Большие сообщения и вложения

Многострочный текст можно вставить в поле ввода обычной вставкой: переносы сохраняются и сами по себе не отправляют сообщение. В длинной строке видно окно вокруг курсора и количество символов. `Ctrl+J` добавляет перенос, `Ctrl+A` и `Ctrl+E` перемещают курсор в начало и конец. `Enter` отправляет сообщение.

Если сообщение превышает 12 000 символов, harness сохраняет его полностью в локальный UTF-8 файл и передаёт агенту только ссылку на него. Агент читает текст частями через `read_attachment`. Для этого нужен подключённый MCP-коннектор; полный текст не вставляется в поле ChatGPT одним сообщением. Файлы больших сообщений хранятся в `~/.chatgpt-coder/attachments/<session-id>/` и остаются на диске после очистки экрана или удаления вложения из списка.

- `/attach` открывает выбор файла или изображения на Windows. Можно указать путь: `/attach "C:\путь\к\файлу.pdf"`.
- На Windows вставь скриншот в поле сообщения через `Ctrl+V` или перетащи туда файл изображения: он появится во вложениях и отправится вместе с сообщением. Вставка из буфера зависит от того, передаёт ли терминал событие вставки; если нет, используй `/attach clipboard`. Если терминал запущен администратором, Windows может не разрешить перетаскивание из обычного Проводника.
- `/attach clipboard` прикрепляет изображение из буфера обмена Windows; `/attach folder` открывает выбор папки. На других системах используй `/attach <путь>`.
- Файлы и изображения отправляются в ChatGPT вместе со следующим сообщением. Допускается до 10 файлов и 50 МБ суммарно; доступность форматов и загрузки зависит от аккаунта ChatGPT. При ошибке загрузки сообщение не отправляется, а вложения остаются выбранными.
- Папка остаётся доступной в текущей сессии до `/detach`. Агент работает с её реальными файлами через `attached_directory_tool`; обычные подтверждения записи и команд сохраняются. `/attachments` показывает ID и пути, `/detach <id>` убирает выбранное вложение, `/detach all` снимает все активные вложения. Исходные файлы и папки не удаляются.

### Цели

Команда `/goal <задача>` запускает цель в текущей сессии. Если ChatGPT завершил ответ, а цель ещё не отмечена выполненной или заблокированной, harness продолжает работу в том же чате. Агент сообщает результат через `update_goal`; незавершённый план, ожидающее подтверждение или фоновая задача не позволяют ему отметить цель выполненной. Статус цели виден над планом, подробности доступны через `/goal status`.

Если ChatGPT показывает устаревший список инструментов без `update_goal`, harness объясняет ему совместимый способ сообщить результат через `update_plan`. Проверки завершения цели при этом сохраняются, а план не заменяется.

Во время работы `Esc` останавливает текущий ход и ставит цель на паузу; `/goal pause` делает то же явно, `/goal resume` продолжает её, а `/goal cancel` отменяет. Отказ или тайм-аут одного подтверждения отклоняет только соответствующий инструментальный вызов: вся цель не ставится на паузу, агент может выбрать безопасную альтернативу или сообщить о реальной блокировке. Ошибка целого хода помечает цель как `blocked`, а не как пользовательскую паузу. Если после трёх продолжений не появилось новых действий инструментов, цель также помечается заблокированной, чтобы избежать бесконечного цикла. После перезапуска активная цель остаётся в сессии на паузе: проверь результат прерванных действий перед `/goal resume`. Обычные сообщения без `/goal` не включают этот режим. Оценка выполнения основана на сообщении модели и состоянии плана: автоматически доказать выполнение произвольной задачи harness не может.

При возобновлении можно передать уточнение, например `/goal resume Продолжай, используй папку src`. Цель останется прежней, а уточнение попадёт в историю и станет новым сообщением для агента. Для очень длинного уточнения действует тот же механизм сохранения в файл, что и для обычных сообщений.

Ответы берутся из HTML области сообщения ChatGPT и преобразуются в Markdown для терминала. Заголовки, списки, ссылки, код, таблицы и доступный исходный LaTeX формул сохраняются по мере возможностей страницы. Это восстановленная разметка: исходный текст модели побайтно веб-интерфейс не предоставляет. За основу подхода взят [codex-chatgpt-web](https://github.com/miuuyy/codex-chatgpt-web).

Интерфейс открывается на отдельном экране терминала. После выхода через `/quit` или `Ctrl+C` прежнее содержимое терминала возвращается, а агент выводит `Bye`.

`/model` показывает доступные модели GPT из открытого ChatGPT, а `/effort` — уровни рассуждения для выбранной модели. Harness умеет открывать выбор модели через название текущего effort в панели Thinking effort возле поля ввода. Для ползунка доступны Low, Medium и High. Выбери пункт по номеру, например `/model 1` или `/effort 2`, либо по имени: `/effort high`. При смене модели выбери effort заново. `/model default` и `/effort default` отключают сохранённое переопределение и оставляют текущие настройки сайта.

### SSH

Агент может вызывать `ssh_exec` для удалённых команд, а `ssh_upload` и `ssh_download` — для передачи отдельных файлов через SFTP. Нужны локальные OpenSSH (`ssh` и `sftp` в PATH), настроенный ключ или SSH-агент и заранее проверенный ключ сервера в `known_hosts`. Поддерживаются алиасы из `~/.ssh/config`. Перед каждым действием действует обычная политика подтверждений; длинную SSH-команду можно отправить в фон и затем смотреть через `/jobs`. Локальные пути передачи ограничены workspace. Пароли и содержимое закрытых ключей передавать в чат не нужно.

`/yolo` или `/approval never` автоматически разрешает все локальные действия harness, включая команды и SSH-передачи. `/approval ask` снова включает запросы подтверждения. Если ранее действие было явно отклонено, агент не повторяет его без новой просьбы пользователя; после такой просьбы действует текущий режим.

## Обновление

Установленный harness проверяет GitHub Releases при запуске и затем каждые пять минут (пока агент работает). Если установленную сборку нельзя надёжно сравнить с опубликованной, агент сообщит об этом, но не будет устанавливать обновление автоматически. Чтобы скачать последний опубликованный выпуск и установить его:

```text
/update check
/update latest
/update apply
```

Источник по умолчанию — `angyedz/chatgpt-web-coder`. `/update latest` скачивает ZIP и проверяет его SHA-256 по метаданным GitHub; `/update apply` подтверждает установку. Источник можно изменить через `/update source owner/repository`, а автоматическую проверку отключить командой `/update autocheck off`. Поддерживаются публичные релизы GitHub.

После загрузки или выбора файла над строкой ввода остаётся подсказка `Approval required: /update apply`. Она исчезает после подтверждения установки или `/update cancel`.

После обновления harness сравнивает имена, описания и схемы MCP-инструментов двух установленных версий. Если они изменились, появится подсказка: настройки аккаунта ChatGPT → Plugins → шестерёнка → имя настроенного коннектора → внизу **Refresh tools**. Закрыть подсказку можно через `Ctrl+R`; если сравнение не удалось, интерфейс сообщит об этом отдельно. При обновлении со старой версии подсказка появится после перезапуска.

Локальный ZIP также можно выбрать в установленном harness:

```text
/update
/update apply
```

После установки перезапусти агент. Для выбора файла без диалога используй `/update "C:\путь\к\update.zip"`. Откат: `/update rollback`, затем `/update apply` и перезапуск. Обновления не подписаны: отображаемый SHA-256 помогает определить файл, но не подтверждает его автора.

После успешного обновления установщик удаляет старые управляемые релизы и временные файлы установки. Текущий и предыдущий релизы сохраняются для работы и одного отката; версии, занятые другими процессами, пропускаются. История, настройки, вложения и общий браузер не очищаются. Если не удалось безопасно проверить процессы или каталоги, очистка пропускается, а обновление остаётся установленным.

### Собрать файл обновления

Из полной папки исходников запусти:

```powershell
.\build-update.cmd
```

Сборщик установит зависимости во временную папку, скомпилирует приложение и Windows-лаунчер и создаст ZIP в `dist\updates`. Нужны интернет, Node.js 22+ с npm и компилятор .NET Framework 4.x. На компьютере получателя установка может загружать зависимости и браузер. Перед выпуском измени версию в `package.json` и `package-lock.json`.

### Автоматические релизы на GitHub

**Два канала:** ветка `main` публикует стабильный GitHub Release, а ветка `pre-release` — отдельный Pre-release после успешных Windows CI, тестов и проверки SHA-256. Остальные ветки и pull request **только проверяются**, но не публикуют релиз. Строго одна ветка отвечает за предварительные сборки.

Управление обновлениями прямо в терминале:

```text
/update settings
/update settings channel pre-release
/update settings autocheck on
/update check
/update latest
/update apply
/update settings channel stable
```

Настройки сохраняются на диске и переживают перезапуск. По умолчанию выбирается безопасный канал `stable`. `pre-release` выбирается явно; он может быть нестабилен. Даже при автопроверке установка требует подтверждения `/update apply`. Для совместимых репозиториев можно изменить источник командой `/update settings source owner/repository`.

Для публикации используется отдельный проверяющий workflow GitHub Actions (`workflow_run`) из `main`: он сверяет SHA-256, источник сборки и вшитые в ZIP метаданные. Неуспешная сборка никогда не публикуется.

## Данные и доступ

- Настройки, учётные данные, профиль браузера и сессии по умолчанию находятся в `~/.chatgpt-coder/`. Они могут содержать ключи и историю переписки.
- Файловые инструменты ограничены workspace; shell-команды выполняются с правами текущего пользователя. По умолчанию команды и записи требуют подтверждения.
- Результаты инструментов передаются в ChatGPT. Настраивай подтверждения и доступ к проектам с учётом содержимого данных.
- Автокомпактация использует приблизительную оценку токенов: точный внутренний счётчик ChatGPT Web недоступен.
- Интерфейс ChatGPT Web и доступность MCP могут меняться. Для поиска необходим SearXNG.
