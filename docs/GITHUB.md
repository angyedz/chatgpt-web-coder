# Публикация на GitHub

[English version](GITHUB.en.md) · [Обзор проекта](../README.md)

## Подключение репозитория

Создай пустой репозиторий на GitHub и выбери нужную видимость. Папка проекта уже содержит локальный Git-репозиторий. Из неё добавь адрес созданного репозитория и отправь ветку `main`:

```powershell
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Замени `OWNER/REPOSITORY` на свой адрес. Если `origin` уже настроен, проверь его командой `git remote -v` перед отправкой. Не добавляй локальные `.env`, ключи, сессии и логи: они исключены в `.gitignore`.

## Проверки и релизы

Workflow [windows-release.yml](../.github/workflows/windows-release.yml) работает так:

1. Каждый push в `main` и каждый pull request запускает Windows runner.
2. Runner устанавливает зависимости и Chromium для тестов, проверяет типы, запускает тесты и собирает ZIP через `scripts/build-update.ps1`.
3. Если все шаги прошли, push в `main` или ручной запуск на `main` создаёт GitHub Release с тегом `build-<run-id>-<attempt>` для проверенного коммита. Pull request релиз не публикует.
4. К релизу прикрепляются `chatgpt-coder-windows.zip` и `SHA256SUMS.txt`. Тот же ZIP можно распаковать для установки или выбрать через `/update`. Установка скачивает необходимые зависимости и браузер.

Начиная с 0.2.5 установленный harness также может проверить и скачать последний публичный выпуск через `/update check` и `/update latest`, затем пользователь подтверждает установку командой `/update apply`. Во время GitHub Actions в ZIP добавляются данные о репозитории и коммите, чтобы после установки можно было сравнивать сборки. Для локального ZIP и старых выпусков идентификатор сборки может быть неизвестен.

Тег уникален для запуска, даже если версия в `package.json` осталась прежней. Чтобы пользователи видели новую версию в самом приложении, измени версию в `package.json` и `package-lock.json` перед выпуском. Повторный запуск workflow создаёт отдельный релиз. Более старый запуск, завершившийся после нового коммита, не назначается **Latest**.

Для ручного запуска открой **Actions → Windows CI and release → Run workflow**, выбери `main`. Нужны разрешённые GitHub Actions и возможность дать встроенному `GITHUB_TOKEN` право `contents: write`; отдельный секрет не требуется. При политике организации, запрещающей это право или указанные Actions, настройка политики должна быть изменена администратором. Если релиз не появился, открой журнал соответствующего запуска Actions.

GitHub сравнивает целевой коммит релиза с основной веткой при проверке прав на файлы workflow. Если более старый параллельный запуск завершился после изменения `.github/workflows/`, GitHub может отклонить его публикацию встроенным токеном; подробности видны в журнале. Повторный запуск на актуальном `main` создаст релиз актуального коммита.

При публикации `SHA256SUMS.txt` позволяет проверить целостность файла, но не является цифровой подписью автора. Не выкладывай ZIP из недоверенного источника.
