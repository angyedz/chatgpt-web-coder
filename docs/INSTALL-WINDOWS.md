# Установка chatgpt-coder на Windows

[English version](INSTALL-WINDOWS.en.md) · [Обзор на русском](../README.md)

## Что потребуется

- Windows 10/11 x64 и подключение к интернету. На Windows ARM64 используется x64-версия через эмуляцию.
- Полная папка с исходным кодом проекта, включая `install.cmd`, `scripts`, `src`, `package.json` и `package-lock.json`.
- После публикации на GitHub полный ZIP также можно скачать в разделе **Releases**: `chatgpt-coder-windows.zip` подходит для установки и обновления.
- Аккаунт ChatGPT, в котором разрешено подключение custom MCP servers, и доступ к OpenAI Platform для создания Secure MCP Tunnel. Сам установщик не создаёт аккаунты, туннель и ключ.
- Для локального веб-поиска — работающий SearXNG с JSON API. Если доступен запущенный Docker Desktop, установщик попробует настроить его автоматически.

Системный Node.js, Git и права администратора для установки самого harness не нужны. Windows PowerShell 5.1 и компилятор .NET Framework 4.x обычно уже присутствуют в Windows. Загрузка браузера и зависимостей занимает место на диске и может занять несколько минут.

## 1. Установить

Открой PowerShell **в папке проекта**, затем выполни:

```powershell
.\install.cmd
```

Либо напрямую:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1
```

Если запускаешь установщик двойным щелчком, сначала **полностью распакуй ZIP**. Окно покажет результат и останется открытым до нажатия клавиши. Журналы установки сохраняются в `%LOCALAPPDATA%\chatgpt-coder\logs`; при ошибке сохрани сообщение и последний журнал.

Установщик скачивает Node.js 24, portable Git, npm-зависимости, Chromium для Playwright и `tunnel-client`. Для архивов Node.js, Git и `tunnel-client` проверяется SHA-256 по данным соответствующего поставщика; npm использует lock-файл проекта, а Chromium устанавливает Playwright. Создаётся настоящий `chatgpt-coder.exe`, а каталог установки добавляется в **пользовательский** PATH.

Если Docker доступен и API `127.0.0.1:8888` ещё не работает, установщик пытается поднять контейнер `chatgpt-coder-searxng` с JSON API, доступный только на localhost. При отсутствии или остановленном Docker он выводит предупреждение: установка harness завершается, но `web_search` потребует SearXNG. Установка Docker Desktop и настройка WSL могут требовать прав администратора и перезагрузки, поэтому установщик не выполняет их автоматически.

По умолчанию программа устанавливается в `%LOCALAPPDATA%\Programs\chatgpt-coder`. Другой каталог можно указать так:

```powershell
.\install.cmd -InstallDir 'D:\Apps\chatgpt-coder'
```

Начиная с версии 0.2.0 можно обновиться из самого harness:

1. Скачай ZIP новой версии из доверенного источника.
2. Введи `/update` и выбери ZIP в открывшемся окне. Или передай путь: `/update "C:\Users\Name\Downloads\update.zip"`.
3. Проверь показанные версию, путь и SHA-256. Введи `/update apply` для установки или `/update cancel`, чтобы отменить выбор.
4. После сообщения об успешной установке закрой и снова запусти `chatgpt-coder` в нужной папке.

Начиная с версии 0.2.5 можно получать обновления из публичных GitHub Releases. По умолчанию используется `angyedz/chatgpt-web-coder`: последний опубликованный выпуск проверяется при запуске и затем каждые пять минут, а при обнаружении другой сборки появляется уведомление. Если метаданных установленной версии не хватает для сравнения, агент показывает отдельное предупреждение и предлагает `/update check`. Введи `/update check`, затем `/update latest`, чтобы скачать и проверить ZIP, и `/update apply`, чтобы подтвердить установку. После этого перезапусти harness. Существующая версия без этих команд сначала обновляется из ZIP обычным способом.

Используй `/update settings` для просмотра канала, репозитория и автопроверок. Выбирай `/update settings channel stable` (по умолчанию, ветка `main`) или `/update settings channel pre-release` (только сборки ветки `pre-release`). Настройка сохраняется на диске; `/update check` и `/update latest` используют её. Для другого источника используй `/update settings source owner/repository`, чтобы выбрать другой публичный GitHub-репозиторий с файлом `chatgpt-coder-windows.zip` в Releases. `/update source` показывает текущий источник, `/update autocheck off` отключает проверку при запуске, `/update autocheck on` включает её снова. `CHATGPT_CODER_UPDATE_REPOSITORY` при запуске переопределяет сохранённый источник. Приватные релизы и ввод GitHub-токенов не поддерживаются. Если у локально собранной версии нет данных об исходном релизе, проверка покажет, что сравнение сборок невозможно. Если последний релиз старее запущенной версии, перед установкой будет предупреждение.

Время установки может быть заметным: подготавливаются новый runtime, Git, npm-зависимости и Chromium, поэтому может понадобиться интернет. Запущенный `tunnel-client` не заменяется. Файлы предыдущих версий остаются в `releases`, а настройки, учётные данные и сессии не удаляются. До завершения штатной установки выбранной остаётся старая версия. Для возврата после перезапуска введи `/update rollback`, затем `/update apply` и ещё раз перезапусти harness. Если в восстановленной старой версии нет команды обновления, вернись к новой через её `install.cmd`.

При ошибке журнал можно открыть командой `/update log`; он хранится в `~/.chatgpt-coder/updates/update.log` и может содержать пути и вывод установщика. Если после аварийного завершения остался файл блокировки `.update.lock` в каталоге установки, удали его вручную только после того, как убедишься, что другой процесс обновления не работает.

SHA-256 показывает идентификатор выбранного файла и позволяет обнаружить его изменение после выбора. При скачивании из GitHub он сверяется с метаданными файла в Releases. Хеш **не является подписью издателя**: проверяй источник, поскольку установщик и npm-скрипты будут выполняться с твоими правами.

Первоначально функцию `/update` нужно установить вместе с версией 0.2.0 через `install.cmd`: более старый harness ещё не знает этой команды. Как альтернатива обновлению из приложения, можно закрыть harness и повторно запустить установщик из папки новой версии. Если `tunnel-client.exe` занят другим процессом при такой переустановке, закрой этот процесс и повтори установку.

Для распространения полной папки установки автор проекта может собрать архив командой `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1`. ZIP появится в `dist\chatgpt-coder-windows-setup.zip`; он содержит исходники и установщик, но не `.env`, локальный `harness.config.json`, ключи или сессии. Если файл уже существует, укажи новый `-OutputPath`. Получатель распаковывает ZIP и выполняет `install.cmd`. Установщик не скачивает сам проект из интернета, пока для него не опубликован и не указан адрес распространения.

## Как собрать файл обновления

После изменений в исходниках запусти **`build-update.cmd`** в полной папке проекта. Он установит зависимости по lock-файлу во временной папке, скомпилирует приложение и Windows-лаунчер и создаст `dist\updates\chatgpt-coder-update-<версия>-<дата>.zip`. Окно покажет путь и SHA-256 и останется открытым. Для сборки нужны интернет, Node.js 22+ с npm (подойдёт runtime установленного chatgpt-coder) и компилятор .NET Framework 4.x.

На GitHub workflow `.github/workflows/windows-release.yml` делает то же после успешных проверок для каждого push в `main` и публикует ZIP и SHA-256 в Releases. Pull request проверяется без публикации. Для ручного запуска выбери этот workflow во вкладке Actions и запусти его на `main`. В настройках организации или репозитория может потребоваться разрешить Actions и право `contents: write` для `GITHUB_TOKEN`.

Перед выпуском новой версии измени её в `package.json` и обеих записях версии в `package-lock.json`. Архив содержит скомпилированное приложение, лаунчер, исходники и установщик; личные `.env`, `harness.config.json`, сессии и ключи в него не включаются. Файл можно выбрать в harness командой `/update`, а затем подтвердить через `/update apply`. Версия 0.2.0 примет архив и соберёт исходники при установке; версии с поддержкой предварительно собранного приложения используют его без повторной компиляции. Установка зависимостей и браузера по-прежнему может требовать интернет. Файл обновления не подписан.

Из PowerShell также доступна команда `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-update.ps1`; параметр `-OutputPath` позволяет задать путь к новому ZIP без перезаписи существующего файла.

## 2. Открыть в нужной папке

Открой **новый терминал**, перейди в любой проект и запусти:

```powershell
cd 'C:\путь\к\проекту'
chatgpt-coder
```

Рабочей папкой агента становится текущая папка терминала. Запускать программу из папки установки не нужно. В установленном процессе доступны собственный Node.js и npm, а если Git не найден в системном PATH — portable Git. Другие языки, SDK и зависимости конкретного проекта устанавливаются отдельно по требованиям этого проекта.

Если `chatgpt-coder` не найден, открой новое окно терминала. Для текущего окна PowerShell можно обновить PATH:

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path', 'Machine') + ';' + [Environment]::GetEnvironmentVariable('Path', 'User')
Get-Command chatgpt-coder -All
```

При установке по стандартному пути можно запустить программу напрямую: `& "$env:LOCALAPPDATA\Programs\chatgpt-coder\chatgpt-coder.exe"`. Если `Get-Command -All` показывает другую программу с таким же именем раньше нужной, скорректируй порядок пользовательского PATH.

## 3. Подключить ChatGPT и инструменты

Один раз выполни настройку:

1. При первом запуске войди в ChatGPT в открывшемся браузере.
2. Создай туннель в [OpenAI Platform → Tunnels](https://platform.openai.com/settings/organization/tunnels). Туннель должен быть связан с нужным ChatGPT workspace. Для создания нужны разрешения **Tunnels Read + Manage**; для работы клиента — **Tunnels Read + Use**. Подробности: [официальная инструкция Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).
3. Создай runtime API key с правами **Tunnels Read + Use** в [Platform → API keys](https://platform.openai.com/settings/organization/api-keys).
4. В строке harness, не в PowerShell, введи:

   ```text
   /connect tunnel tunnel_...
   /connect key <твой-runtime-ключ>
   ```

   Вместо примеров вставь свои значения. ID туннеля и имя коннектора сохраняются в пользовательских настройках и доступны в других папках. Ключ сохраняется в `~/.chatgpt-coder/credentials.json` в профиле пользователя; файл не зашифрован приложением, не пересылай его и не добавляй в репозиторий.
5. В [ChatGPT Plugins](https://chatgpt.com/) добавь custom MCP server: **+ → Add custom MCP server → Connection: Tunnel**, выбери созданный туннель. Для встроенного локального MCP установи Authentication: None, ознакомься с предупреждением и создай/установи коннектор. Подробности: [официальная инструкция OpenAI](https://developers.openai.com/plugins/deploy/connect-chatgpt).
6. Назови коннектор `chatgpt-coder`, либо сохрани своё имя в harness командой `/connect name <имя>`.
7. Дождись зелёного индикатора `tunnel`. Если коннектор не виден, проверь доступность custom MCP в аккаунте, принадлежность туннеля workspace и режим temporary chat. Команды `/doctor`, `/tunnel` и `/status` помогают найти проблему.

Для проверки без запуска интерфейса можно выполнить `chatgpt-coder --doctor`. Эта команда проверяет локальную конфигурацию и доступность MCP; она не подтверждает, что ChatGPT успешно вызовет инструмент. Если `tunnel-client` отсутствует, его можно скачать заново через `chatgpt-coder --install-tunnel` или `/connect install`.

## Настройки и данные

- `%LOCALAPPDATA%\Programs\chatgpt-coder\chatgpt-coder.exe` — программа запуска по умолчанию.
- `%LOCALAPPDATA%\Programs\chatgpt-coder\releases` — установленные версии программы, Node.js и portable Git.
- `%LOCALAPPDATA%\Programs\chatgpt-coder\browsers` — Chromium, используемый установленной программой.
- `%USERPROFILE%\.chatgpt-coder\config.json` — общие настройки подключения; `credentials.json` — ключ туннеля.
- `%USERPROFILE%\.chatgpt-coder\browser` и `sessions` — профиль браузера и локальные сессии. Они могут содержать конфиденциальные данные.
- `harness.config.json` и `.env` в текущем workspace — локальные настройки проекта. Порядок применения: значения по умолчанию, пользовательский `config.json`, настройки проекта, переменные окружения. `HARNESS_CONFIG` заменяет путь к проектному JSON.

Переменная `CHATGPT_CODER_HOME` меняет каталог пользовательских данных harness. Чтобы убрать программу, удали её каталог из пользовательского PATH и затем удали каталог установки через Проводник. Профиль, ключи и сессии находятся отдельно и сохранятся, пока ты не удалишь их самостоятельно.

## Если что-то не работает

- **Установка оборвалась на загрузке:** проверь доступ к `nodejs.org`, npm registry, GitHub и серверам загрузки Playwright. Повтори установку; прежняя выбранная версия сохраняется до успешного завершения.
- **При выборе ZIP ошибка `ENOENT` с текстом `#< CLIXML`:** в версиях до 0.2.2 введи путь к архиву вручную: `/update "C:\путь\к\обновлению.zip"`, затем `/update apply`. После установки 0.2.2 и перезапуска окно выбора снова доступно.
- **Окно сообщает об ошибке:** посмотри этап и сообщение в окне или открой последний файл в `%LOCALAPPDATA%\chatgpt-coder\logs`. При обращении за помощью приложи журнал, предварительно убрав личные данные и ключи, если они в нём есть.
- **Команда не найдена:** открой новый терминал и проверь `Get-Command chatgpt-coder -All`.
- **Chromium не стартует:** запусти установщик повторно; браузер лежит внутри каталога установки, а не в системном Chrome.
- **Не работает веб-поиск:** установи и запусти Docker Desktop и повтори установку либо укажи готовый SearXNG через `SEARXNG_URL`. Для контейнера установщика проверь `docker logs chatgpt-coder-searxng`.
- **Туннель не подключается:** проверь ID, ключ, разрешения, связь туннеля с ChatGPT workspace и лог из команды `/tunnel`.
- **Настройка работает в одной папке, но не в другой:** проверь локальные `.env`, `harness.config.json` и переменные окружения: они могут переопределять общие настройки.
