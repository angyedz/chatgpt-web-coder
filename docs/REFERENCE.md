# chatgpt-coder — справочник

[English version](REFERENCE.en.md) · [Краткий обзор](../README.md)

Локальный coding-харнесс, в котором **ChatGPT Web — это мозг**, а ваша машина — руки.

Вы пишете запрос в терминале. Харнесс открывает ChatGPT в Chromium через Playwright, создаёт временный чат, отправляет контракт инструментов и ждёт ответа. Когда ChatGPT вызывает инструмент через MCP-коннектор, вызов проходит по **OpenAI Secure MCP Tunnel** в локальный MCP-сервер, исполняется на машине, а результат возвращается в тот же ответ ChatGPT. Финальный ответ стримится в TUI.

```text
┌──────────────────── TUI (Ink) ────────────────────┐
│ чат · tool-карточки · план · аппрувы · статусы     │
└───────────────────────┬───────────────────────────┘
                        │ события, turn_id
┌───────────────────────▼───────────────────────────┐
│ Orchestrator                                       │
│ сессии · политика · роутинг · отмена               │
└──────────┬────────────────────────────┬────────────┘
           │                            │
┌──────────▼──────────┐       ┌─────────▼───────────┐
│ Playwright          │       │ MCP server (HTTP)   │
│ ChatGPT Web         │       │ exec · patch · fs · │
│ temporary chat      │       │ grep · searxng      │
└──────────┬──────────┘       └─────────▲───────────┘
           │                            │ JSON-RPC
           │                  ┌─────────┴───────────┐
           └─────────────────▶│ OpenAI tunnel-client│
                              └─────────────────────┘
```

## Возможности

- **ChatGPT Web как модель** — для самой модели используется веб-аккаунт; для Secure MCP Tunnel нужен отдельный runtime API key.
- **Полный локальный tool loop** — терминал, файлы, патчи, поиск, картинки.
- **Codex-style инструменты**: `exec_command` + `write_stdin`, `apply_patch`, `read_file`, `list_dir`, `glob`, `grep`, `update_plan`, `view_image`, `web_search`, `web_fetch`.
- **SearXNG** для веб-поиска.
- **TUI на Ink** — стриминг ответа, карточки инструментов, план, аппрувы, статусы браузера/MCP/туннеля.
- **Approvals** — shell и записи требуют подтверждения (`y`/`n`), либо `--yolo`.
- **Path jail** — файловые операции не выходят за workspace.
- **Async shell-сессии** — длинные команды переживают лимит MCP-запроса (~90–120 с): `exec_command` возвращает `session_id`, дальнейший вывод забирается через `write_stdin`.
- **Таймеры и фоновые задачи** — напоминания, отложенный запуск команды, ограничение времени команды и управление фоновыми процессами и инструментами.
- **Автоподключение коннектора** — харнесс вставляет `@chatgpt` в композер и проверяет pill коннектора перед каждым сообщением.
- **Контекст с автокомпактацией** — настраиваемый ориентир до 1 млн токенов, индикатор в TUI и сжатие истории в свежий чат перед достижением лимита.
- **Подключение из TUI** — установка tunnel-client, сохранение Tunnel ID и Platform key командами `/connect`.
- **Git-инструменты** — отдельные инструменты для статуса, diff и истории коммитов.
- **Восстановление зависшей генерации** — если после инструмента план ещё не завершён и веб-чат долго не двигается, харнесс может остановить ответ и продолжить задачу в том же чате.

## Требования

- Windows-установщик скачивает собственные Node.js 24 и Git; для разработки из исходников нужен Node.js 22+.
- Windows 10/11, macOS или Linux.
- Аккаунт ChatGPT с доступом к Developer Mode / custom MCP connectors.
- OpenAI Platform: `tunnel_id` и runtime API key с правами **Tunnels Read + Use**.
- Для `web_search` нужен SearXNG с включённым JSON API. Установщик попытается запустить его, если Docker уже работает; см. [SearXNG](#searxng).

## Быстрый старт

### Windows: установка и запуск из любой папки

Открой PowerShell в полной папке проекта и запусти:

```powershell
.\install.cmd
```

Установщик скачает Node.js, Git, зависимости, Chromium и tunnel-client, затем добавит `chatgpt-coder.exe` в пользовательский PATH. Открой **новый терминал**, перейди в нужный проект и запусти:

```powershell
cd 'C:\путь\к\проекту'
chatgpt-coder
```

При первом запуске войди в ChatGPT и настрой туннель через `/connect`. Подробные шаги, расположение файлов, обновление и устранение проблем: [Установка на Windows](INSTALL-WINDOWS.md).

### Запуск из исходников

```powershell
npm install
npm run setup          # Chromium для Playwright + tunnel-client
Copy-Item .env.example .env
# заполните TUNNEL_ID и CONTROL_PLANE_API_KEY
npm run dev
```

При первом запуске откроется Chromium. Войдите в ChatGPT вручную. После появления композера харнесс продолжит сам.

Проверка:

```powershell
npm run doctor
npm test
npm run typecheck
```

## Tunnel и коннектор ChatGPT

1. Откройте [Platform → Tunnels](https://platform.openai.com/settings/organization/tunnels), создайте туннель и скопируйте `tunnel_...`.
2. Создайте runtime API key в [Platform → API keys](https://platform.openai.com/settings/organization/api-keys). Нужны права **Tunnels Read + Use**.
3. Введите в harness `/connect tunnel tunnel_...` и `/connect key <runtime-ключ>`. Эти настройки подключения доступны из разных папок. При разработке также можно использовать `.env` в текущем проекте:

```dotenv
TUNNEL_ID=tunnel_...
CONTROL_PLANE_API_KEY=sk-...
```

4. Запустите харнесс. В TUI индикатор `tunnel` должен стать зелёным. Если нет — смотрите `~/.chatgpt-coder/tunnel/chatgpt-coder.log`, команда `/tunnel` покажет пути.
5. В ChatGPT (аккаунт/workspace должен разрешать custom MCP и write actions) включите **Developer Mode** и создайте custom MCP server/plugin: [Settings → Connectors](https://chatgpt.com/#settings/Connectors) → **Advanced → Add custom MCP server** (в новом UI — **Plugins → + → Add custom MCP server**). Connection: **Tunnel**, выберите свой туннель. Authentication: **None**. Permissions: **Allow all actions**. Установите plugin (Install), чтобы он появился в меню `@`.
6. Имя коннектора должно **точно** совпадать с `browser.connectorName` (по умолчанию `chatgpt-coder`). Харнесс сам вставляет упоминание `@chatgpt` в композер и проверяет, что коннектор прикреплён к каждому сообщению.
7. Временный чат должен быть **Personalized**: в unpersonalized temporary chat плагины/коннекторы отключены. Выбор запоминается аккаунтом; харнесс пытается выбрать Personalized автоматически, если видит этот диалог.
8. Напишите запрос в TUI. В логе хода должно появиться `Attached connector: chatgpt-coder`. Если соединение с туннелем ещё не готово, создание коннектора может упасть — дождитесь зелёного индикатора `tunnel` и повторите Create.

> Если ChatGPT не показывает коннектор в меню `@`, проверьте: Developer Mode включён, коннектор создан под тем же аккаунтом/workspace, туннель запущен (`/tunnel`), temporary chat — Personalized. В крайнем случае отключите временный чат: `"useTemporaryChat": false` в `harness.config.json`. Для browser-only режима без инструментов: `"attachConnector": false`.

Клавиши: `Enter` — отправить, `Esc` — отменить ход, `Ctrl+C` — отменить/выйти, `Ctrl+D` — диагностика в том числе во время работы, `y`/`n` — аппрув.

Зажмите левую кнопку и протяните по тексту сообщения: выделенное содержимое автоматически копируется при отпускании. В буфер попадает только текст сообщений, без подписей и элементов интерфейса harness. Колесо мыши и `PgUp`/`PgDn` прокручивают историю. В терминалах вне Windows копирование использует OSC 52 и зависит от поддержки буфера обмена терминалом.

Многострочная вставка не отправляется до Enter; `Ctrl+J` вставляет перенос. На Windows `Ctrl+V` прикрепляет изображение из буфера, если терминал передаёт событие вставки; если событие не приходит, используйте `/attach clipboard`. Перетащенный файл изображения прикрепляется, когда терминал передаёт его путь. Windows может запрещать перетаскивание из обычного Проводника в терминал, запущенный от администратора. Сообщения длиннее 12 000 символов сохраняются в `~/.chatgpt-coder/attachments/<session-id>/` и передаются модели как ссылка на файл для чтения частями через `read_attachment`. Для этого нужен MCP-коннектор. Файлы и картинки загружаются в ChatGPT при следующей отправке (до 10 файлов и 50 МБ суммарно); папки остаются подключёнными к сессии, пока их не снимут через `/detach`, и доступны через `attached_directory_tool` с обычными подтверждениями. Вложение убирается из списка без удаления исходного файла с диска. Если загрузка не удалась, проверьте вложения в браузере перед повтором.

### Цели и субагенты

Цель переходит в `paused` только через явное действие пользователя (`Esc`, `/goal pause`) или закрытие harness. Внутренний/неожиданный abort не считается пользовательской паузой и переводит активную цель в `blocked`. Отказ или тайм-аут отдельного подтверждения отклоняет только этот инструментальный вызов: цель остаётся активной. Обычное ожидание, завершение или ошибка дочернего агента не меняют состояние родительской цели. Продолжение после блокировки — `/goal resume`.

`/swarm start 1-5 <задача>` запускает до пяти агентов в независимых фоновых вкладках ChatGPT, даже пока основная цель продолжает работать. Каждый получает локальную копию текущей рабочей папки, включая незакоммиченные изменения, но секреты (`.env`, приватные ключи, cloud credentials и аналогичные файлы) исключаются. Запуск не выполняет Git-команды, не создаёт ветки/worktree и не требует GitHub или PR. Фоновые вкладки создаются без переключения фокуса окна. После завершения вкладка остаётся открытой; `/swarm chat <id>` показывает переписку, `/swarm open <id>` выводит вкладку вперёд только по явной команде, а `/swarm message <id> <текст>` отправляет follow-up в исходный чат. Главный Orchestrator получает MCP-инструменты для запуска, ожидания, проверки, уточнения и остановки дочерних агентов, но использует их только после явного разрешения пользователя.

При завершении агентские изменения интегрируются в исходный workspace только для файлов, которые не менялись в нём после создания копии. Совпадающие результаты не дублируются; конфликтующие файлы не перезаписываются и остаются в локальной копии агента. Путь к копии, интегрированные файлы и конфликты доступны через `/swarm status`, `/swarm inspect <id>` и `/swarm report <run-id>`. Копии и отчёты сохраняются локально в `~/.chatgpt-coder/`.
### Обновление Windows-версии

Скачай ZIP новой версии и введи `/update` в harness: откроется выбор файла. Можно указать путь напрямую, например `/update "C:\Users\Name\Downloads\chatgpt-coder-windows-0.3.0.zip"`. Harness покажет версию и SHA-256; команда `/update apply` подтверждает установку, `/update cancel` отменяет выбор. После установки закрой и заново запусти `chatgpt-coder`.

Новая версия подготавливается отдельно; при обычной ошибке до переключения остаётся прежняя. Для возврата к предыдущей версии введи `/update rollback`, затем `/update apply` и перезапусти программу. История, настройки и ключи не удаляются. Загрузка Node.js, Git, npm-пакетов и Chromium может потребовать интернет; используемый `tunnel-client` при таком обновлении сохраняется. Сам запущенный процесс продолжает работать на старой версии до перезапуска.

После успешного обновления установщик удаляет старые каталоги управляемых релизов, сохраняя текущую и предыдущую версии для одного отката. Релизы, используемые работающими процессами, пропускаются. Незавершённые каталоги установки с проверенной структурой удаляются только через шесть часов; непроверенные каталоги и каталоги с ссылками пропускаются. Загруженные установочные архивы удаляются после подготовки релиза, а каталог, созданный неудачной текущей установкой, удаляется при возможности. Общий Chromium, сессии, вложения и настройки очистка не затрагивает. Если проверка процессов или путей не удалась, обновление сохраняется, а очистка пропускается с предупреждением.

Чтобы после изменений собрать ZIP обновления, запусти `build-update.cmd` из папки проекта. Результат появится в `dist\updates`; архив содержит собранное приложение и совместим с `/update`. Установка зависимостей и браузера на компьютере получателя по-прежнему может требовать интернет. Подробности — в [инструкции для Windows](INSTALL-WINDOWS.md).

Обновления не имеют цифровой подписи: отображаемый SHA-256 идентифицирует выбранный файл и защищает от его замены после выбора, но не подтверждает автора. Устанавливай только доверенные ZIP-архивы: их установочный код выполняется с правами пользователя. Команда доступна в установленной Windows-версии начиная с 0.2.0; для её первоначального появления установи 0.2.0 через `install.cmd`. Подробности и создание архива описаны в [инструкции для Windows](INSTALL-WINDOWS.md).

### Локальные сессии

Сессии сохраняются автоматически в `~/.chatgpt-coder/sessions/` по отдельности для каждого workspace; `CHATGPT_CODER_HOME` меняет базовый каталог. При следующем запуске автоматически открывается последняя выбранная сессия. Сохраняются сообщения, вызовы инструментов и их результаты, план, сжатая память и последние зафиксированные сведения о задачах и таймерах. Ввод `/connect key` и сами запросы подтверждения не записываются в историю команд, но переписка, аргументы и результаты инструментов могут содержать секреты: файлы сессий являются конфиденциальными локальными данными. На Unix файлы создаются с правами `0600`; на Windows используются права каталога пользователя.

После перезапуска или переключения сессии следующий запрос открывает новый веб-чат и передаёт в него ограниченную выжимку сохранённой истории и плана. Это не точное восстановление временного или сохранённого чата ChatGPT; длинная история может быть сокращена. `/sessions` показывает сохранённые сессии, а `/session open <id>` открывает локальную историю выбранной сессии. Последние незавершённые ответы помечаются как прерванные, а для не завершившихся вызовов инструментов результат считается неизвестным. При восстановлении harness не отправляет предыдущий запрос повторно и не перезапускает процессы или таймеры.

Фоновые процессы, фоновые вызовы и таймеры после выхода из harness автоматически не перезапускаются. Их последнее записанное состояние доступно через `/session info` и `/session job <id>`; для текущих процессов используйте `/jobs`. При переключении сессии работающие фоновые процессы могут продолжать работу, а переключение во время выполняющегося вызова инструмента, фонового вызова инструмента или ожидающего подтверждения откладывается. Снимок состояния задач может устареть, если задача завершилась, пока была открыта другая сессия. Запись сессии выполняется с небольшой задержкой, поэтому внезапное завершение процесса может потерять последние изменения.

### Таймеры и фоновая работа

Например, `/timer 10m перерыв` покажет уведомление через десять минут, а `/timer 30s -- npm run dev` запустит сервер через 30 секунд. Текущие таймеры и фоновые задачи видны над строкой ввода. Их списки и вывод доступны в журнале с прокруткой PgUp/PgDn. Таймеры и задачи живут в текущем процессе harness: при выходе ожидающие таймеры отменяются, а процессы останавливаются.

Агент может запустить сервер через `exec_command` с `background: true`; для обычной команды можно указать `timeout_ms`, чтобы остановить её по истечении времени. Уже запущенную сессию с `session_id` можно перевести в фон через `background_exec_session`. `start_background_task` запускает другой инструмент асинхронно, а `get_background_task` возвращает его результат. Фоновые процессы переживают отмену текущего хода. Подтверждения для команд и изменений действуют как обычно; команда, которую агент ставит на таймер, подтверждается при установке таймера.

Процессную задачу можно остановить через `/job stop <id>` или `kill_exec_session`. Не все другие инструменты поддерживают прерывание после запуска, поэтому общий фоновый вызов нельзя принудительно отменить. Отмена ожидающего таймера не останавливает команду, которая уже успела запуститься.

### Восстановление после зависания ChatGPT

Если после вызова инструмента план остаётся незавершённым и браузер показывает генерацию без нового текста или инструментов в течение 90 секунд, харнесс пробует остановить ответ и продолжить задачу в том же чате. Во время выполняющегося инструмента, фонового вызова инструмента или ожидающего подтверждения восстановление не запускается. Продолжение отправляется только после подтверждённой остановки и ограничено двумя попытками. Если ответ завершился после инструмента, пока фоновый вызов ещё работает или ожидает подтверждения, автоматическое продолжение пропускается; результат можно посмотреть через `/jobs` и продолжить вручную.

Порог можно изменить через `browser.stallRecoveryMs` в `harness.config.json` (миллисекунды); `0` отключает автоматическую остановку. Длительные рассуждения модели тоже могут выглядеть как зависание, поэтому для сложных задач можно увеличить порог.

Если браузер был закрыт, при следующем запросе harness попробует заново подключить страницу и передаст в новый чат ограниченную историю текущей сессии. Предыдущий запрос повторно не отправляется. Если не удалось подтвердить остановку генерации или начало ответа, проверьте браузер перед повтором: уже начатые действия могут продолжаться. `/status` и `Ctrl+D` показывают наблюдаемые признаки работы браузера, инструменты и подтверждения; состояние Web UI само по себе не доказывает, что удалённое действие остановилось.

### Внешние MCP-серверы

Harness может сам подключаться к внешним MCP-серверам через `stdio` или Streamable HTTP. ChatGPT использует их через уже подключённый коннектор `chatgpt-coder`: инструменты `mcp_list_servers`, `mcp_list`, `mcp_call_tool`, `mcp_read_resource` и `mcp_get_prompt`. В `mcp_list` можно выбрать `tools`, `resources`, `resource_templates` или `prompts`; если сервер вернул `nextCursor`, его можно передать в следующем запросе. При `approvalMode: "ask"` каждый вызов внешнего инструмента требует подтверждения, даже если сервер объявляет его безопасным.

В строке ввода harness:

```text
/mcp list
/mcp add-http docs https://example.com/mcp
/mcp add-stdio files npx -y @modelcontextprotocol/server-filesystem C:\\projects
/mcp connect files
/mcp tools files
/mcp logs files
/mcp disconnect files
/mcp remove files
```

Серверы также можно описать в `harness.config.json`. Процесс stdio запускается при подключении, без командной оболочки, и закрывается при выходе. Аргументы с пробелами в `/mcp add-stdio` заключайте в кавычки; для сложной конфигурации используйте JSON:

```json
{
  "mcpServers": {
    "files": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\projects"],
      "env": { "API_KEY": "${MY_MCP_API_KEY}" }
    },
    "docs": {
      "transport": "http",
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${MY_MCP_TOKEN}" }
    }
  }
}
```

Можно добавить такую запись командой `/mcp add-json <имя> <JSON объекта сервера>`. `${ИМЯ}` подставляется из переменной окружения при подключении; задайте её до запуска harness. Процесс stdio получает ограниченный набор переменных окружения и явно указанные `env`. Конфигурация сохраняется в проекте, поэтому секреты следует передавать через переменные окружения. HTTP с заголовками поддерживается; интерактивная авторизация OAuth и старый SSE-транспорт пока не реализованы. Внешние серверы имеют собственные права и не ограничены файловой песочницей встроенных инструментов.

### Skills и AGENTS.md

Навыки обнаруживаются в `.agents/skills`, `.codex/skills`, `.claude/skills` и `.chatgpt-coder/skills` проекта, а также в пользовательских `~/.agents/skills`, `~/.codex/skills` и `~/.chatgpt-coder/skills`. Каждый навык — каталог с `SKILL.md`, где YAML-заголовок содержит `name` и `description`. Дополнительные каталоги можно указать в `skills.paths`; при совпадении имени приоритет имеют дополнительные пути, затем проектные, затем пользовательские. Каталог и описания видны через `/skills` и инструмент `list_skills`; полные инструкции и файлы внутри каталога навыка читаются по запросу инструментом `read_skill`.

Инструкции `AGENTS.md` загружаются от родительских каталогов к корню workspace. `AGENTS.override.md` заменяет `AGENTS.md` на том же уровне. Для вложенных папок агент вызывает `get_project_instructions`; `read_file` и `list_dir` также возвращают применимые инструкции. `/agents путь` показывает их в harness. Инструкции внутри `.codex/AGENTS.md` корня проекта тоже учитываются. Для отдельных файлов действует ограничение 20 000 символов, общий лимит — 60 000 символов. Команды оболочки и внешние MCP-серверы сами по себе не гарантируют соблюдение этих инструкций.

### Быстрое подключение

После запуска выполните `/connect install`, затем задайте ID туннеля и ключ:

```text
/connect tunnel tunnel_...
/connect key <Platform runtime key>
```

Ключ хранится отдельно от workspace в `~/.chatgpt-coder/credentials.json`; на Unix права файла ограничены владельцем. Затем создайте custom MCP connector в настройках ChatGPT и укажите имя через `/connect name <name>`. `/doctor` покажет, какие соединения готовы.

### Контекст и компактация

По умолчанию лимит оценки — 200 000 токенов. Настроить его можно в TUI командой `/context 256k` или в `harness.config.json`:

```json
{ "context": { "maxTokens": 256000 } }
```

Харнесс оценивает размер по тексту запросов и ответов и перед отправкой очередного запроса сравнивает оценку с 80% лимита. При достижении порога он просит ChatGPT составить handoff summary, открывает новый чат и добавляет summary к следующему запросу. `/compact` запускает это вручную. Это приблизительная оценка: ChatGPT Web не предоставляет харнессу точный счётчик токенов и внутреннее состояние своей истории.

## Конфигурация

Общий конфиг находится в `~/.chatgpt-coder/config.json`. В текущем проекте можно создать отдельный `harness.config.json` командой `chatgpt-coder --init` (или `npm run dev -- --init` при запуске из исходников). Настройки применяются в порядке: значения по умолчанию → общий конфиг → конфиг проекта → переменные окружения. Пример проектного конфига:

```json
{
  "approvalMode": "ask",
  "browser": {
    "headless": false,
    "useTemporaryChat": true,
    "newChatPerTurn": false,
    "modelLabel": "",
    "connectorName": "chatgpt-coder",
    "attachConnector": true,
    "autoApproveToolCalls": true
  },
  "mcp": { "host": "127.0.0.1", "port": 8790, "path": "/mcp" },
  "tunnel": { "enabled": true, "tunnelId": "tunnel_...", "healthPort": 8791 },
  "searxng": { "url": "http://127.0.0.1:8888", "categories": "general", "language": "auto" }
}
```

Переменные окружения имеют приоритет: `TUNNEL_ID`, `CONTROL_PLANE_API_KEY`, `SEARXNG_URL`, `MCP_PORT`, `CHATGPT_MODEL_LABEL`, `CHATGPT_CONNECTOR_NAME`, `HARNESS_ATTACH_CONNECTOR`, `HARNESS_APPROVAL`, `HARNESS_HEADLESS`, `HARNESS_SHELL`.

`CHATGPT_EFFORT_LABEL` также может переопределить сохранённый уровень рассуждений. `/model default` и `/effort default` снимают сохранённые переопределения; переменные окружения снова применяются при следующем запуске. Варианты берутся из меню ChatGPT и зависят от аккаунта и модели. Если меню недоступно или изменилось, harness сообщит об ошибке, а не станет незаметно использовать другой вариант.

Для SSH нужны `ssh` и `sftp` из OpenSSH в PATH. Настрой вход по ключу через SSH-агент или стандартный `~/.ssh/config`, заранее проверь и добавь host key в `known_hosts` обычным SSH-клиентом. Инструменты используют пакетный режим и строгую проверку host key, не запрашивают пароли и используют общую политику подтверждений. SSH-команды выполняются на удалённой машине; передача файлов ограничена отдельными локальными файлами внутри workspace. Задания можно запускать в фоне через `ssh_exec` с `background=true` или `start_background_task` и отслеживать как обычные процессы.

### SearXNG

`web_search` ходит в JSON API SearXNG по `SEARXNG_URL` (по умолчанию `http://127.0.0.1:8888`).

В `settings.yml`:

```yaml
search:
  formats:
    - html
    - json
```

Проверка: `http://127.0.0.1:8888/search?q=test&format=json`.

#### Локальный инстанс (Windows + WSL2 + Docker)

Ниже приведён пример существующего Docker-контейнера внутри WSL2-дистрибутива `archlinux`
(порт публикуется только на `127.0.0.1`, наружу ничего не открыто). Скрипт управления рассчитан на эту конкретную конфигурацию; установщик Windows при доступном Docker Desktop создаёт отдельный контейнер `chatgpt-coder-searxng`.

```
WSL2 (archlinux, systemd)
└── docker.service
    └── searxng  (образ searxng/searxng:latest, 127.0.0.1:8888 -> 8080)
```

Конфиг: `/opt/searxng/settings.yml` внутри WSL (`use_default_settings: true`, `limiter: false`,
`search.formats: [html, json]`, свой `secret_key`). Переменная окружения:
`SEARXNG_URL=http://127.0.0.1:8888` в `.env`.

Управление из Windows:

```powershell
npm run searxng status    # состояние keep-alive, контейнера и JSON API
npm run searxng start     # поднять WSL/докер/контейнер, дождаться HTTP 200
npm run searxng restart
npm run searxng stop
npm run searxng logs      # docker logs --tail 80
```

Скрипт: `scripts/searxng.ps1`.

Важно: WSL2 выключает виртуальную машину, когда в ней не остаётся сессий, поэтому
контейнер умирает вместе с ней. Автозапуск решён двумя вещами:

- контейнер запущен с `--restart unless-stopped`, `docker.service` включён в systemd;
- в папке «Автозагрузка» лежит `searxng-keepalive.vbs`, который держит скрытую сессию
  `wsl -d archlinux -e sleep infinity` — то есть WSL2 и докер живут постоянно.

Удалить автозапуск: удалить `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\searxng-keepalive.vbs`
и выполнить `wsl --shutdown`.

Если SearXNG не нужен, ничего делать не надо: `web_search` вернёт понятную ошибку
(`SearXNG is unreachable ... Check SEARXNG_URL`), остальные инструменты работают.

## Безопасность

- MCP-сервер слушает только `127.0.0.1`.
- Каждый вызов MCP должен содержать `turn_id` активного запроса. После отмены, завершения или запуска нового запроса старые вызовы отклоняются; фоновые команды и инструментальные задачи прекращаются при отмене создавшего их хода.
- Туннель исходящий: входящие порты не открываются.
- Telegram использует исходящий HTTPS long polling. Управлять harness может только один привязанный Telegram user ID из привязанного личного чата; сообщения из групп и других аккаунтов игнорируются. Три случайных слова для привязки действуют 10 минут; допускается до 5 попыток с аккаунта и 20 всего. Статус, запрос, ответ и кнопки обновляются в одном сообщении с ограничением частоты правок.
- Токен Telegram вводится в скрытое поле и не записывается в историю harness. На Windows он шифруется DPAPI для текущего пользователя; на Unix системах файл учётных данных создаётся с правами `0600`. Удалить токен можно через `/telegram unlink` или отозвать у BotFather.
- Файловые инструменты ограничены workspace; shell-команды выполняются с правами текущего пользователя.
- Shell и записи по умолчанию требуют аппрува. `--yolo`/`/approval never` снимает защиту.
- В режиме `never` все локальные подтверждения harness автоматически разрешаются, в том числе для SSH и передачи файлов. Параметр `require_approval` в старых схемах инструментов сохраняется для совместимости, но не меняет режим. При переключении в `never` ожидающие подтверждения тоже разрешаются. Чтобы повторить явно отклонённое ранее действие, пользователь должен снова попросить его выполнить; затем применяется текущий режим.
- Профиль браузера — чувствительный артефакт. Не делитесь `~/.chatgpt-coder/browser`.
- Результаты инструментов уходят в ChatGPT. Не подключайте чужие/секретные репозитории без понимания рисков.
- В транскрипте, плане, уведомлениях и подтверждениях управляющие последовательности терминала удаляются перед отображением. Исходные аргументы команд и данные инструментов при этом не изменяются. Прерванные ответы помечаются как `interrupted`.

## Ограничения текущей версии

- DOM-селекторы ChatGPT могут меняться; слой селекторов вынесен в `src/browser/selectors.ts`.
- Один активный ход за раз. Параллельные чаты — следующий этап.
- Компактация основана на приблизительной оценке: точный внутренний контекст ChatGPT Web недоступен.
- `web_search` требует доступный SearXNG.
- Tunnel-client, Developer Mode и custom MCP connector создаются вручную.
- Коннектор должен быть доступен в выбранном режиме чата; unpersonalized temporary chat его не видит.
